# 立法（RULES.md）— ルールの正本（SSOT）
立法Bot（bots/ritsuho.md）が管理。CONSTITUTION.md に従属する。司法チェック（judiciary/check.sh）は条番号で判定する。

- R1 各段の出力 `goals/*/0N-*/output.md` は見出し `## 承認` を持ち、`状態:` と `承認者:` を書く。
- R2 `状態: 承認済み` のとき `承認者:` は人の名前でなければならない（AI/Bot/Grok 等は不可）。
- R3 秘密情報らしき文字列（APIキー、トークン、`password=` 等）を含めない。
- R4 前段が `承認済み` でない段は `未着手` か `停止中` でなければならない（承認ゲート）。例外: 前段の状態に「デモとして自動進行」と明記した場合のみ次段を進めてよい。
- R5 Collection の事実には出典（URL か Issue 番号）を付ける。
- R6 CONSTITUTION.md の変更は人のレビュー（CODEOWNERS）を通す。
- R7 `templates/goal/` の4段すべてに `## 承認` 欄がある（テンプレートの健全性）。
- R8 Operation の「伝播」で出た学びは、RULES.md は立法が改正案を出し、CONSTITUTION.md は人だけが変える。
- R9 行政の成果物（`goals/*/03-construction/deliverables/*.md`）は、「安全です」と断定しない・リンクを押させない・パスワードを求めない。必ず「公式アプリから確認」を案内し、`司法チェック:` 欄を持つ。（#12 の詐欺メールの悩みに基づく）
- R10 Webログ検知レポート（`goals/*/04-operation/reports/*.md`）の各検知行（`- 検知`）は、根拠の行番号 `L<数字>` と検知ルール番号 `W<数字>`（goals/weblog-defense/rules/detection-rules.tsv）を持つ。根拠のない検知は誤検知の疑いとして差し戻す。
- R11 レポートは断定表現（「確実に」「間違いなく」「100%」「攻撃者である」）を使わない。「疑い」として書く。
- R12 対策は提案のみ。自動適用・自動反映の指示（「適用しました」「自動で反映」「apply」等）を書かない。レポートには `承認: 人の承認が必要（未）` の行を置く。
